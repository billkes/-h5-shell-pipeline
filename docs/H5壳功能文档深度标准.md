# H5 壳功能文档深度标准

> **生效范围**：`h5_shell` / `h5_flutter_shell` / `h5_swift_shell` / `h5_oc_shell`  
> **校验时机**：`build.agent` 产出 → `plan.gate` 硬拒  
> **目标**：功能完整、业务有深度、表达专业 — 在 **无登录 / 无云同步** 前提下，用 H5 域模型 + Bridge 组合达标。

配套：《H5壳Flutter产品要求.md》§4 · `prompts/h5_shell/phase_pm_ui_plan.txt` · `scripts/batch/spec_business_depth.py`

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| **完整 ≠ 功能多** | 主流程闭环 + 辅流程 + 全边界态，优于堆空页 |
| **复杂在业务层** | 实体、规则、状态机、指标口径写在 H5；不引入账号/后端 |
| **专业可执行** | 术语、计算规则、导出字段写死，Implementer 可直接照做 |
| **写了必须实现** | 禁止 optional / may / 可选项；gate 按 tier 硬校验 |

## 2. 深度分级（businessDepthTier）

由 `skill-input/context.json` → `constraints.businessDepthTier` 写入；默认按 CSV `coreScene` + `localFeature` + `productFlow` 推断，**兜底 L2**。

| Tier | 标签 | 典型场景 | 实体 | 规则 BR-xx | 主流程步数 | 辅流程数 × 步数 | 术语表 | 指标导出 |
|------|------|----------|------|------------|------------|-----------------|--------|----------|
| **L1** | record | 清单 / 备忘 / 打卡 | ≥3 | ≥5 | ≥10 | 1 × ≥6 | ≥6 | 0 |
| **L2** | control | 预算 / 提醒 / 库存管控（**默认**） | ≥3 | ≥7 | ≥12 | 2 × ≥6 | ≥8 | ≥1 |
| **L3** | analytics | 统计 / 对比 / 周期报告 | ≥4 | ≥9 | ≥14 | 2 × ≥8 | ≥10 | ≥2 |

**升级关键词**（自动 L3）：`stat|analytics|report|compare|trend|dashboard|insight|forecast`  
**L2 关键词**：`budget|remind|inventory|control|ledger|track|spend|预算|提醒|采购|到期`

手动覆盖：在 `task.csv` 增加列 `业务深度`（值 `L1`/`L2`/`L3`）— 后续 `task fill` 写入 context；当前由 `resolve_business_depth_tier()` 推断。

## 3. 功能文档.md 强制章节（英文，按序）

### 3.1 App Theme & Screen Inventory
- 主题叙事一段；**Screen Inventory** 表为 **PM 唯一页面真相源** — 只列本包需要的 H5 路由（Splash / Welcome / Legal / Plaza / Store 等**非默认必有**，由 PM 按产品决定）
- 壳侧屏仅：WebView host、错误兜底、Launch 占位

### 3.2 Domain Model & Data Contract
- 表：Entity | Fields | Type | Validation | Persistence key
- 实体数 ≥ tier；含派生字段（如余额、到期天数）
- 关系：1:N / 聚合 / 计算字段说明

### 3.3 Business Rules Engine
- 编号 **BR-01 … BR-NN**（≥ tier 下限）
- 每条：触发条件 · 计算/判定 · 冲突策略 · 用户可见反馈
- 示例：预算扣减顺序、免费次数 vs 金币、到期 lead time

### 3.4 Primary Workflow
- 逐步编号（1. 2. 3. …），**≥ tier 主流程步数**
- 每步：UI 动作 + 数据变更 + 成功/失败反馈
- 须引用 BR-xx 与 Bridge 步骤

### 3.5 Secondary Workflows
- **≥ tier 辅流程数**，每条 **≥ tier 辅流程步数**
- 典型：编辑归档、筛选复盘、充值后继续

### 3.6 State & Empty Matrix
- 表：Screen/Flow | Loading | Empty | Error | Permission-denied | Offline-retry
- 主业务屏每行 4+ 态；**禁止** generic "No data"

### 3.7 Professional Surface
- **Domain Glossary**：≥ tier 术语数（英文用户可见文案）
- **Metrics & Reports**：≥ tier 指标数（字段、口径、周期）
- **signature H5 interaction**：1 个，**绑定 Primary Workflow 具体步骤**（禁纯视觉花样），且须在 **Tab 1（Hub Home）首屏可达**

### 3.8 4.2 Native Offset
- ≥3 项壳/Bridge 能力 + 用户场景
- 每项映射 **Primary Workflow 步骤编号**

### 3.9 Bridge Capability Matrix
- 能力 | Workflow step | 入参 | 出参 | 失败 UX（引用 Bxx）

### 3.10 既有章节（保留）
- Export / Save Flow · IAP Catalog & Free Tier · §H5 Architecture · App Store Listing（英文）

## 4. plan.gate 校验清单

默认 **软警告续跑**（见《H5壳交互拓扑与PlanGate策略.md》）；`STRICT_PLAN_GATE=1` 时以下亦硬拒。

脚本：`spec_business_depth.verify_spec_business_depth()`（归类为 SOFT）

| 编号 | 检查项 |
|------|--------|
| SPEC-001 | 文档长度 ≥ tier.min_chars |
| SPEC-002 | 强制章节标题存在（Domain Model / Business Rules / Primary Workflow / …） |
| SPEC-003 | BR-xx 数量 ≥ tier |
| SPEC-004 | Primary Workflow 编号步骤 ≥ tier |
| SPEC-005 | Secondary Workflow 区块数 ≥ tier |
| SPEC-006 | Domain Glossary 词条 ≥ tier |
| SPEC-007 | Metrics 定义 ≥ tier |
| SPEC-008 | 4.2 Native Offset ≥3 项 |
| SPEC-009 | signature interaction 引用 workflow 步骤 |
| SPEC-010 | 禁止 optional / may / 可选项 模糊措辞 |

## 6. Buildioo（L2）验收样例

**实体**：SupplyItem · BudgetLedger · ReminderEntry  
**规则**：BR-01 预算上限 · BR-02 记账 · BR-03 chip 筛选 · BR-04 到期 lead · BR-05 免费导出 · BR-06 金币 gate · BR-07 重复项合并  
**主流程 12 步**：Welcome → Home → chip → 新增 item → 预算校验 → 拍照 attach → 设到期 → 保存 ledger → 列表筛选 → 导出周报卡 → IAP 不足 → Settings/Plaza  
**辅流程**：A 编辑软删 · B 按 tag/date 复盘  
**指标**：Weekly spend total · Items due within 7 days
