### Native Bridge Contract — LOCKED (match the shell EXACTLY)
The native shell (Part 2) registers ONE WKScriptMessageHandler and replies on ONE global callback. The H5 bridge MUST reuse these EXACT names — never derive them from the code prefix:
- Send: `window.${BRIDGE_CHANNEL}.postMessage({ id, action, payload })` — the shell injects `window.${BRIDGE_CHANNEL}` at documentStart (`window.webkit.messageHandlers.${BRIDGE_CHANNEL}.postMessage(...)` is equivalent).
- Receive: define `window.${BRIDGE_CALLBACK} = (id, envelope) => { /* match id → resolve envelope.data / reject envelope.error */ };`.
- Request envelope is an OBJECT, not a JSON string: `{ id, action, payload }`.
- Reply envelope: success `{ id, data }`; error `{ id, error: { code, message } }`.
- Wrong channel/callback name ⇒ native never receives the message and EVERY bridge call silently falls back to the JS stub (IAP / device / file all break with no error). `${BRIDGE_CHANNEL}` / `${BRIDGE_CALLBACK}` are derived from the App name and are non-negotiable.
